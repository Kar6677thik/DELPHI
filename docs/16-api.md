# 16 — API contract

Base path `/api/v1`. JSON over HTTPS. The OpenAPI 3.1 document is generated by FastAPI and
checked into `backend/openapi.json` (regenerate with `uv run delphi openapi`). CI fails if the
generated file differs from the committed one (schema-first discipline, EFG §7). Every operation
documents its error body as a `default` response of `application/problem+json` with the
`Problem` schema (§1). Frontend types are generated from it with
`openapi-typescript` into `frontend/src/api/schema.d.ts`, and CI checks that file too.

## 1. Conventions

| Topic | Rule |
|---|---|
| Auth | Session cookie `delphi_session` (httpOnly, Secure, SameSite=Strict). Every endpoint except `/health`, `/ready` and `/auth/login` requires a session |
| CSRF | Mutating requests MUST carry the header `X-Delphi-Csrf: 1` and an `Origin` equal to the configured public origin; otherwise `403 CSRF_REJECTED` |
| IDs | UUIDv7 strings |
| Money | `*_paise` integers. The API never sends float rupees |
| Probabilities | `{hypothesis_key: float}`, 6 decimals |
| Time | RFC 3339 UTC strings (`…Z`) |
| Pagination | Keyset: `?limit=50&cursor=<opaque>`; response `{items, next_cursor}`. Max limit 200 |
| Idempotency | `Idempotency-Key` header (UUID) REQUIRED on: create Guardian session, probe response, evidence request, disposition, chase operation, lien approvals, job creation. The same key and same body returns the stored response; the same key with a different body returns `409 IDEMPOTENCY_CONFLICT`. Keys are kept 24 h |
| Concurrency | Mutable aggregates return `ETag: "<version>"`. Mutations need `If-Match`; a mismatch returns `412 VERSION_CONFLICT` |
| Errors | RFC 9457 `application/problem+json`: `{type, title, status, detail, code, instance, request_id, errors?: [{path, code, message}]}` |
| Request id | `X-Request-Id` is accepted or generated, and echoed in the response and the logs |
| Rate limits | Login: 5 failures / 15 min per (username, IP) → `429 RATE_LIMITED`. Global: 20 req/s per session, token bucket with burst 40 |

### Error codes (stable)

`VALIDATION_FAILED` (422), `UNAUTHENTICATED` (401), `FORBIDDEN` (403), `CSRF_REJECTED` (403),
`NOT_FOUND` (404), `IDEMPOTENCY_CONFLICT` (409), `INVALID_STATE_TRANSITION` (409),
`VERSION_CONFLICT` (412), `RATE_LIMITED` (429), `INVALID_CLIENT_SIGNALS` (400),
`PROBE_NOT_AWAITING` (409), `KB_VALIDATION_FAILED` (422), `FOUR_EYES_REQUIRED` (409),
`SHADOW_INSUFFICIENT` (409), `KB_STALE_PARENT` (409), `JOB_ALREADY_RUNNING` (409),
`NOT_INITIALISED` (503: dataset or models not ready yet; returned by Guardian, Navigator,
Chase and Scout write endpoints), `INTERNAL` (500).

## 3. Server-Sent Events

`GET /api/v1/events/stream` with `Accept: text/event-stream`. Each event:

```
id: <outbox_events.id>
event: <type>
data: {"type": "...", "entity_id": "...", "at": "...", "payload": {...}}
```

Event types: `guardian.session.updated`, `guardian.session.decided`, `case.opened`,
`case.updated`, `evidence.narrative_ready`, `campaign.updated`, `chase.updated`,
`chase.lien.updated`, `job.updated`, `scout.cluster.created`, `kb.version.changed`,
`sim.transfer` (demo feed). A heartbeat comment (`: ping`) is sent every 15 s. Reconnect with
`Last-Event-ID` replays from `outbox_events` (retained 24 h). SSE payloads are small: clients
re-fetch the entity via REST.
